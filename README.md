# Практическая работа 1, вариант 8

Эмулятор UNIX-подобной командной строки на Python. Первые пять коммитов
соответствуют этапам задания: REPL, конфигурация, ZIP-VFS, основные
команды, изменение VFS. Состояние каждого этапа можно открыть по его
коммиту.

## Требования и запуск

Нужен Python 3.10 или новее; сторонние пакеты не требуются. Сборка не
нужна. Из корня репозитория в Windows запустите `run.bat` либо
`python -m src.shell`. Во второй команде можно добавить параметры запуска.

```text
python -m src.shell [--vfs PATH] [--startup PATH] [--config PATH]
```

`--vfs-path` и `--startup-script` являются полными вариантами имен флагов.
Без `--vfs` оболочка стартует с пустой виртуальной системой. При наличии
ZIP-образа он читается в память, но не распаковывается на диск. Содержимое
файлов хранится в base64; `rm` и `mkdir` меняют только память процесса.
Корневой файл `/motd`, если он есть, печатается при запуске.

## Конфигурация и стартовый сценарий

`--config` указывает на YAML-файл с простой картой строковых путей:

```yaml
vfs_path: image.zip
startup_script: demo.start
```

Допустимы обычные, одинарные и двойные кавычки. Поддерживаются пустые
строки и комментарии `#`. Значения файла имеют приоритет над CLI;
относительные пути файла отсчитываются от его каталога. Параметры CLI
отсчитываются от текущего каталога ОС. Итоговые значения печатаются
перед запуском сеанса. Ошибка чтения конфигурации завершает программу
с кодом 1.

Стартовый сценарий содержит одну команду оболочки на строку. Пустые
строки и комментарии `#` пропускаются; комментарии внутри строк тоже
распознаются. Ввод и вывод печатаются как в живом диалоге. При ошибке
показываются путь и номер строки, затем программа завершается с кодом 1.

## Команды

| Команда | Действие |
| --- | --- |
| `ls [-a] [-l] [путь ...]` | Список файлов; `-a` показывает скрытые имена, `-l` вид и размер. |
| `cd [путь]` | Переход в каталог VFS; без пути возвращает в корень. |
| `find [путь] [-name шаблон]` | Рекурсивный поиск; шаблон использует `*` и `?`. |
| `who` | Имя пользователя и узла реальной ОС. |
| `echo [-n] [текст ...]` | Вывод текста; `-n` убирает перевод строки. |
| `mkdir [-p] путь ...` | Создание каталогов; `-p` создает предков. |
| `rm [-r] [-f] путь ...` | Удаление; `-r` для каталогов, `-f` игнорирует отсутствие. |
| `exit` | Завершение сеанса. |

Пути внутри VFS имеют UNIX-форму `/home/user/file`. Поддерживаются
абсолютные и относительные пути, `.` и `..`, а также `~` для корня.
Приглашение показывает реального пользователя, имя узла и текущий
каталог VFS. Кавычки объединяют слова в один аргумент.

## Пример использования

Запустите `examples\stage5_commands.bat`. Скрипт создаст временный
ZIP-образ, исполнит `examples\stage5.start`, покажет ошибку удаления
каталога без `-r` и удалит временный образ.

```text
user@host:~$ mkdir -p /scratch/a/b
user@host:~$ cd /scratch/a
user@host:/scratch/a$ find /scratch
/scratch
/scratch/a
/scratch/a/b
user@host:/scratch/a$ cd /
user@host:~$ rm -r /scratch
```

Сценарии `examples\stage2_*.bat`, `stage3_*.bat` и
`stage4_commands.bat` показывают соответствующие функции и ошибки.
Архивы для примеров создаются скриптом `tests.make_fixtures` временно;
они не включены в Git.

## Устройство и проверка

`src/config.py` читает параметры и YAML, `src/vfs.py` хранит образ в
памяти, `src/commands.py` исполняет команды, `src/shell.py` управляет
диалогом и стартовым сценарием. Проверки находятся в `tests`.

```text
python -m unittest discover -s tests -v
```

Для проверки отдельных этапов можно перейти к одному из пяти коммитов,
выполнить эту команду и запустить демонстрационный сценарий этапа.
